# 冻结评测计划（视觉解析模块）

本文件是**计划**，不是结果。执行之前不得根据任何新样本调整规则或阈值。

## 0. 为什么需要这份计划

当前 11 张图**不是**独立测试集，不能用来声称泛化能力。

原因不是阈值调参，而是**功能设计本身看过这批图**。图纸类型划分、"页码或版本"字段组、水印重复度的 n-gram 长度与重复次数、孤立标签的高度判据、字段值规则，全部是在读过这 11 张图（及其真实 OCR 输出）之后成形的。即使数值只在 7 张开发样本上调过，剩下 4 张也已经影响了**设计**。

因此现有 11 张一律称为 **regression set（回归集）**，用途只有一个：改动之后确认没把已经work的东西弄坏。

## 1. 新数据集要求

| 项 | 要求 |
|---|---|
| 数量 | ≥ 20 张，**全新**，与现有 11 张无重叠 |
| 类别覆盖 | 干净 / 模糊 / 倾斜 / 水印 / 印章 / 多设备，**六类各 ≥ 3 张** |
| 图纸类型 | 至少包含一种现有类型表里**没有**的图纸（如屏蔽门、水泵接线图），用于检验 `unknown` 分支是否按预期兜底而不是误判成已有类型 |
| 编号方案 | 至少 5 张使用与现有前缀不同的编号（非 `FAN-`/`PUMP-`），检验字段值规则没有把本数据集的命名写死 |
| 负例 | 至少 2 张**不该触发兜底**的困难干净图（低对比度但字段完整），用于压测误触发率 |

## 2. Gold 标注

- gold 与图片**分开存放**，生成/收集阶段就固化，之后不得修改；
- 每条至少记录：图片哈希、图纸类型、任务所需关键字段及其正确值、是否存在遮挡；
- **增加一个人工判断字段** `human_needs_fallback`：在看到任何模型输出和任何分数之前，由人判断该页是否需要兜底。
  这一步是为了拿到**真正的兜底标签**，摆脱当前 `fallback_proxy_positive`（由 OCR 命中率派生、与命中率共用答案的循环定义）。

## 3. 冻结与执行

1. 冻结提交：记录 commit、`configs/visual_parser.yaml` 全文哈希、`paddleocr`/`paddlepaddle`/模型版本、VLM 模型名与 prompt 版本；
2. **运行一次**，`--ocr-engine paddleocr`（实时推理，不用 fixture）；
3. VLM **禁用缓存**运行，否则延迟、成功率、调用次数都是假的；
4. 结果直接落盘，不做任何"再跑一次看看"。

## 4. 必须报告的指标

沿用回归集口径，外加实时运行才能测到的部分：

- 兜底触发率
- **真实兜底召回率**（对 `human_needs_fallback`，非代理标签）
- **真实误触发率**
- VLM 字段恢复率
- `legacy_containment_hit_rate`（乐观口径，仅用于与历史对比）
- `structured_candidate_recall`
- `conflict_free_exact_rate`（保守口径，对外引用以此为准）
- 字段冲突数 / 非法字段值数 / 设备归属不确定数
- 按触发原因分解的贡献度
- **实时 VLM 子集**：调用次数、成功率、失败原因分布、p50/p95 延迟、重试次数
- **实时 OCR**：单张耗时分布

## 5. 不通过怎么办

**如实记录，不回头调参后冒充盲测。**

若某项指标不达预期：
1. 原样写进报告，注明这是冻结规则下的一次性盲测结果；
2. 允许在**之后**改规则，但改完的结果属于新一轮开发，不得追溯标为本次盲测成绩；
3. 想再要一次盲测，必须再攒一批全新样本。

一次盲测只能用一次。这条没有例外。

## 6. 本轮（第三轮）已知的待验证项

冻结跑之前就能预见、需要新样本才能证伪的几点：

- 字段值规则中 `drawing_no_format` 的 `origin` 是 `dataset_induced`，**由本仓库样本归纳而来**，最可能在新编号方案上误判；
- `equipment_code_charset` 假设编码不含中文——在某些企业的图纸上可能不成立；
- 多设备图纸恒定标记 `group_cardinality_uncertain`，必然全部触发兜底，误触发率会被这一类拉高；
- 回归集上字段冲突数为 0，**冲突逻辑只被单元测试覆盖过，没有被真实数据触发过**。
