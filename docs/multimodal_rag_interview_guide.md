# 局部裁剪 → VLM 复核 → 证据合流 → 二次决策 —— 面试口述稿

> 只写本仓库**真实跑过**的内容。本轮有 **2 次真实付费调用**（用户显式授权，上限 5），
> 其余全部为离线重放或 stub。凡是没跑过的写「未运行」。

---

## 一、一句话

OCR 读完一页图纸后，如果某个关键字段**缺失、非法或与另一来源冲突**，
就按它的 bbox **裁下那一小块**交给视觉模型再读一次，
把两边读数**并存**而不是覆盖，然后**重新做一次决策**。

## 二、为什么不是「OCR 不行就把整页丢给 VLM」

整页兜底有三个致命问题：

1. **贵**。一页的 token 远多于一小块。
2. **模型要先找字段再读字段**，而「找」正是这一层已经做完的事——重做一遍还做得更差。
3. **最要命的是它会编**。给模型一整张图问「控制柜编号是多少」，它会找到一个像编号的东西给你。
   给它一块明确的区域问「这里写的是什么」，它才可能说「看不清」。

所以 `resolve_review_crop` 的最后一级是**拒绝**，不是兜底：

```
value bbox → 标签向右扩展 → 表格单元格 → 整行 → crop_unavailable
```

`crop_unavailable` 直接转 abstain 或人工复核。实测在重度模糊页上就是这么走的。

## 三、我在这一轮实际测到的四件事

### 1. 复核触发面必须先查，不能直接拿去调模型

接手时表格阶段有 60 条复核请求。我先统计了一下：

```
非表头单元格   114
复核请求       60      触发率 52.6%
带可执行 bbox   0
reason 分布  {'CELL_SPANS_COLUMNS': 57, 'HEADER_ATTRIBUTION_UNCERTAIN': 3}
```

**95% 来自同一个原因**，而那个原因在上一轮的坏例审计里已经被测定为**假阳性**——
PaddleOCR 的框比行高，文本其实全对。如果直接把这 60 条丢给 VLM，
预算全部烧在已知的假阳性上，而且报告还会显示「复核了 60 个字段」。

所以配置里给了 `reason_priority`，`cell_assignment_uncertain` 排最后一位（99）。
它仍然合格，但在 `max_live_calls` 截断时排在真正缺失的字段后面。

### 2. 旧缓存冒充不了 cache replay

仓库里原有 64 条 VLM 缓存。看起来可以直接拿来做离线回归，但：

- 它对应的是**整图**：`_call(..., bbox=[])`，bbox 恒为空，传的是整张图；
- 条目里**没有出处**。模型名、prompt 版本、图片 hash 只进了不可逆的 key，
  读出来无法验证。没有时间戳，没有 schema 版本。

所以我新写了缓存，每条自带明文出处，且**不匹配就 raise**：

```python
for name, expected, actual in checks:
    if expected != actual:
        raise CacheVerificationError(...)
```

为什么必须 raise 而不是当作 miss？因为静默 miss 会被当成「无缓存证据」或者触发一次实时调用，
两者都掩盖了「这条记录已经不描述当前输入」这个事实。

### 3. 两个开关，不是一个

```python
if self.cfg.mode == "live" and not (self.cfg.allow_live_vlm and allow_live):
    raise LiveCallNotAuthorised(...)
```

配置里的 `allow_live_vlm` 会被误提交，命令行的 `--allow-live-vlm` 不会。
默认 `mode: disabled` + `allow_live_vlm: false`。

### 4. 两个我自己写出来又测出来的缺陷

**缺陷一：干净页被降级。** 第一版里二次决策无条件执行，
而 `run_second_pass` 会设 `remediation_exhausted=True`。
结果 MM5 干净页从 `execute` 掉到 `partial`——**它因为一次它根本不需要的补救而被惩罚**。
修法：没有触发复核就不跑第二次决策。

**缺陷二：修完缺陷一之后，冲突漏掉了。** MM4 注入的 OCR/VLM 冲突没有产生复核请求
（该页字段齐全），于是第二次决策被跳过，`execute` 保持不变——冲突躺在证据集里没人看。
修法：门槛改为 `targets or fused.conflicts`。**冲突本身就是新信息，不依赖有没有裁图。**

这两个我都写了回归测试。

## 四、合流的四种情况

| 情况 | 结果 |
|---|---|
| OCR=M-13，VLM=M-13 | 不冲突，两条证据都留 |
| OCR=`M - 13`，VLM=`M-13` | **归一化后相同 → 不冲突**，两个 raw 值都原样保留 |
| OCR=FAN-F53-01，VLM=FAN-FS3-01 | **冲突，resolution=unresolved，不自动采信 VLM** |
| OCR 无，VLM 有 | 单源证据，`single_source=true`；**高风险字段不得因此升到 execute** |

这四条直接复用既有的 `merge_evidence`，没有另写一份。另写一份一定会漂移，
而漂移表现为冲突凭空出现或消失。

**追问准备：为什么不信 VLM？** 因为没有理由。模型自报的 confidence 不是业务置信度，
而这条链路上 VLM 从来没有过测量意义上的置信度——我把它记为 `0.0`，
含义是「没有测量到置信度」，不是「不可信」。两边都是机器读数，
其中一个恰好更贵，这不构成采信理由。

## 五、真实测到的结果

水印页 FAN-A23-01：**OCR 平均置信 0.9957，字段完整度 0.1667**——
典型静默漏读，置信度完全看不出问题。裁剪后 2 次真实调用：

```
图号      = FAN-A23-01   （与历史 gold VF16 一致）
断路器编号 = QF-23        （无 gold，未验证）
```

但决策**仍然是 abstain**，因为目标字段 `控制柜编号` 仍然缺失，
且这两个字段都是高风险单源 VLM 读数。**补回字段 ≠ 可以回答。**

## 六、简历上能说和不能说

**能说**：

- 根据 bbox 裁剪局部图片送视觉模型复核；
- Qwen2.5-VL 类模型（网关实际为 `qwen-vl-max`）参与关键字段复核；
- OCR/VLM 证据**字段级**合流，冲突不自动裁决；
- 证据不足时部分回答或拒答；
- **使用历史真实 VLM 结果进行离线回归**（2 条，带完整出处校验）。

**不能说**：

- 不能说实时多模态链路已上线（默认 `disabled`，本轮只授权了 2 次调用）；
- 不能说 VLM 恢复率是某个数字——**没有人工 Gold**，冻结清单 `multimodal_gold` 是 0 文件；
- 不能说默认采用 VLM 结果；
- 不能说视觉检索已接入（本轮不做图片 Embedding、CLIP、向量检索）；
- 不能把 cache replay 的耗时说成模型延迟。
