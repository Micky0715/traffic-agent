## 一、一句话说清楚这一层在干什么

一张图纸上的表格，OCR 给我的是一堆**孤立的文字块加坐标**，它不知道哪两个块属于同一行、
哪个块是表头。这一层的任务是把「一堆带坐标的字」还原成「有行有列有表头的表」，
再切成能被检索的 chunk，并且每个 chunk 都能指回**第几页、哪个 bbox**。

## 二、为什么不能直接把 OCR 文本拼起来当 chunk

一个反例就够了。某台风机的参数表，按坐标从左到右从上到下拼出来是：

```
A16 45kW 28000m3/h A17 55kW 32000m3/h
```

用户问「A16 的功率是多少」，这段文本里**没有任何东西说 45kW 是功率**。检索命中了也没用，
因为下游无法判断该取哪个数。列名必须进文本，这是表格 chunk 和普通文本 chunk 最本质的区别。

## 四、四个我真正想讲的设计点

### 1. 表格区域的阈值必须相对于表格，不是相对于整页

找横线时如果要求「长度 ≥ 页宽的 X%」，图纸右下角那种只占页面四分之一的标题栏就永远找不到。
更糟的是**页面边框会被当成表格的左右边界**——我实测到过一次，
FAN-MULTI-01 本来是 12×2，被识别成 12×4，多出来的两列全是空的。

修法是：先粗定位表格所在的横向带，再**用这条带里横线自身的 x 范围**当左右边界，
而不是用页宽。

```python
rules_only = cv2.morphologyEx(strip, cv2.MORPH_OPEN, rule_kernel)
xs = cv2.findNonZero(rules_only)
left, right = int(xs[:, 0, 0].min()), int(xs[:, 0, 0].max())
```

### 2. OCR 块落格用面积覆盖，而且归一化的分母是「块」不是「格子」

用中心点判断会在跨格的长文本上出错。用面积覆盖时分母选谁很关键：

- 分母取**格子**面积：一个小字落进大格子，覆盖率很低，会被误判为没落进去
- 分母取**块**面积：问的是「这个块有多少比例在这个格子里」，这才是要问的问题

覆盖率低于阈值时**不硬塞**，而是把候选格子都记下来并打 `assignment_uncertain`。
宁可标记不确定，也不要编一个结构出来。

### 3. 多级表头继承必须被共同祖先约束

两级表头：

```
|      参数       | 备注 |
| 功率  |  风量   |      |
```

朴素的「空就继承左边」会让「备注」列拿到路径 `[参数, 风量]`。
但「备注」和「风量」在第一级并**不属于同一个父节点**，不能继承。
约束条件是：只在**共享祖先**的范围内向右继承。这个我踩过，现在有回归测试钉着。

### 4. 没有表头，就不能推断实体列 —— 本轮实测到的真实缺陷

这是我这一轮发现的最有价值的问题。

**现象**：结构审计跑出 `cross_device_contamination 12/48 = 25.0%`。

**定位**：打印真实图纸 FAN-MULTI-01 的行 chunk：

```
entity=A16功率   text='设备A16功率；第2列=45kW'
```

`A16功率` 是**字段名**，不是设备。它被当成设备 ID 了。

**根因**：`infer_entity_column` 用的是「列已填满且取值互不相同」。
这批图纸的标题栏是**两列键值表**：左列是字段名，右列是值。
左列当然填满且互不相同——它完美满足这个判据，但含义完全相反。

**修法**：分两步。

1. **没有表头行就不推断实体列**。左列到底是什么，只有表头能告诉你；没有表头还硬猜，
   就是拿判据的巧合当语义。
2. 把「两列、无表头、左列填满且互不相同」显式识别成 **key/value 布局**，
   行 chunk 产出 `field_name` / `field_value`，`entity_id` 置 `None`。

**效果**：`cross_device_contamination` 25.0% → **0.0%**。

同时 `row_chunks_with_entity` 从 91.7% → **0.0%**。这不是退步：
**这 8 张真实表本来就没有一行代表一台设备**，之前那 91.7% 是假的。
指标降下来是修复的结果，不是代价。

**追问准备**：这样是不是丢了检索能力？没有。字段名本身带设备前缀：

```
field=A16功率  value=45kW  text='A16功率 45kW'
```

「A16 的功率」照样命中。真正的区别是**不再谎称这一行是一台设备**。

## 五、Chunk 结构

| 类型 | 一张表几个 | 文本形态 |
|---|---|---|
| `table_parent` | 1 | 标题；章节路径；列：… |
| `table_row`（实体表）| 每行 1 | `风机参数表；设备A16；参数.功率=45kW` |
| `table_row`（键值表）| 每行 1 | `A16功率 45kW` |

共用已有的 `DocumentChunk`，不另起一套模型——两套模型要分别建索引、分别打分，必然漂移。

每个 chunk 都带 `page_start` / `page_end` / `source_bboxes` / `table_id` / `chunk_id`，
实测**页码可溯源 56/56 = 100%，bbox 可溯源 56/56 = 100%**。
