> **规则作者与压力测试设计者相同，本测试只能用于证伪和发现边界，不能证明泛化能力。**

一次性运行，未调参、未重跑、未因结果回头修改任何规则。

## 3. 五项点名检查

### 3.1 未知类型是否安全降级 —— ❌ **没有**

| 图 | 真实类型 | 检出类型 | 依据 | 兜底 | decision_ready |
|---|---|---|---|---|---|
| ADV04 | 屏蔽门 | `fan_param_table` | field_combination | 否 | 0.83 |
| ADV05 | 变压器 | `fan_wiring` | title | 否 | **1.00** |
| ADV06 | 自动扶梯 | `fan_wiring` | title | 否 | **1.00** |

`unknown` 分支一次都没触发。根因：标题关键词 `接线图` 是**跨设备通用词**，
它是从一个"所有接线图都是风机"的数据集里归纳出来的。变压器、扶梯、屏蔽门图纸
全部命中风机类型，然后以满可作答率交付。

**测试设计缺陷需自曝**：这三张图我仍沿用了 `电机编号／断路器编号／控制柜编号` 的标题栏，
所以字段级检查合格是合理的。真正失败的是**类型判断**——而类型决定套用哪套必需字段、
哪套值规则。若变压器图带的是变压器专有字段，会被按风机清单打分。

### 3.2 漏一台设备是否序号错配 —— ✅ **未发生**，但暴露另一个洞

| 图 | 场景 | 结果 |
|---|---|---|
| ADV09 | 三台乱序绘制（E43,E41,E42） | 按编号正确配对 fan#1=E41 / fan#2=E42 / fan#3=E43，**未使用序号** |
| ADV08 | 末尾设备留空 | OCR 2 台 / VLM 2 台，D31↔D31、D32↔D32 精确对齐，**无错配** |
| ADV07 | 中间设备留空 | **对齐全线失败**：VLM 返回 `device_name="风机组"`，受控映射无此词 → `unknown` → 4 个实体全 single_source，decision_ready 掉到 0.25 |

对齐设计本身扛住了（编号优先、绝不按位置配对）。但：

- ADV07 被「风机组」这个词打穿 —— 冻结清单薄弱点 #7 兑现；
- **ADV08 的 D33 两个来源都没读到，系统完全不知道少了一台。**
  `group_cardinality_uncertain` 虽触发，但它在**每张**多设备图上都触发，等于不携带信息。

### 3.3 一字之差是否被当成两个无关实体 —— ⚠️ **条件未能造出**，撞出更严重问题

三张近似编号图**一次冲突都没产生**，原因不是系统处理得好：

- ADV10 画的是 `M-I9`，**OCR 直接读成了 `M-19`**；
- ADV11 `QF-2B`、ADV12 `A1G` 被两边一致读对，无分歧；
- ADV10/11 **根本没触发兜底**，无第二来源，物理上无法产生冲突。

**ADV10 是本轮最危险的一条：**

```
真值        M-I9
OCR 读成     M-19            ← 字符被静默"纠正"
OCR 置信度   0.997
字段完整度   1.00
值规则       全部通过（M-19 完美符合 ^M- 与 ASCII 字符集）
兜底         未触发
decision_ready  0.83         ← 系统认为这个错值可直接作答
```

**从 OCR 到值规则到路由到接收策略，七层信号无一报警。**
字符级静默错误是当前体系的完全盲区：所有信号都在「字段／实体」粒度，
没有任何一个能看到「这个字符本该是 I 不是 1」。

### 3.4 格式合规但不存在的编号是否被放行 —— ❌ **全部放行**（如预测）

| 图 | 值 | invalid | valid_ratio | 兜底 | decision_ready |
|---|---|---|---|---|---|
| ADV13 | `M-777` / `QF-888` / `FAN-CAB-999` | 无 | 1.0 | 否 | **1.00** |
| ADV14 | `M-0` / `QF-00000` / `FAN-CAB-0` | 无 | 1.0 | 否 | **1.00** |
| ADV15 | 页码 **`9/1`**（第9页/共1页） | 无 | 1.0 | 否 | **1.00** |

`9/1` 逻辑上不可能存在，却完美匹配 `^[0-9]+ ?/ ?[0-9]+$`。
**形状规则原理上无法判断存在性。** 这条证伪干净、可预期，正是台账校验存在的理由。

### 3.5 decision_ready 是否因路由漏检而高估 —— ✅ **确实高估**

```
人工标注应兜底 11 条 → 实际触发 6 条 → 漏检 5 条（召回 54.5%）
漏检：ADV10、ADV11、ADV16(印章)、ADV19(倾斜)、ADV20(低对比度)
```

其中 ADV11/16/19/20 侥幸读对，未造成损失；**ADV10 造成了实际损失**——
错值 `M-19` 被判定为 0.83 可作答。

这验证了实现时写下的注释：`decision_ready` 把「路由判定无需兜底」视为归属可信，
因此**它继承路由的准确率**。路由召回 54.5%，这个口径就至少高估同等幅度。

## 4. 唯一一次真实冲突

```
ADV18（重度模糊）
  字段        图号
  OCR 值      FAN-F53-01     validation=valid     ← 正确
  VLM 值      FAN-FS3-01     validation=unknown   ← 把 5 读成了 S
  entity_ref  null（页级字段）
  resolution  unresolved
```

冲突逻辑本身工作正常（记录不裁决）。**注意方向：OCR 对、VLM 错**——
这与第三轮 `_cross_check_device_id` 中写死的「倾向采用 VLM 结果」假设方向相反。
那条倾向性假设第一次被真实数据挑战。

## 5. 逐条失败分层归因

| case | ready | 失败层 | 说明 |
|---|---|---|---|
| ADV01 | 0.83 | **格式规则** | `PSD/2026/017` 违反 `drawing_no_format`(dataset_induced)、`M/12` 违反 `motor_prefix` —— 合法编号被误拒 |
| ADV02 | 0.83 | **格式规则** | `TR_01_A`、`M_01_A` 下划线不在 `equipment_code_charset` 字符集 |
| ADV03 | 0.83 | **格式规则** | `电机三号`、`信号柜三号` 中文编号被 ASCII 假设拒绝 |
| ADV04 | 0.83 | **类型判断** | 屏蔽门图 → `fan_param_table`；漏 `2/4` |
| ADV07 | 0.25 | **VLM 映射 → 实体对齐** | `风机组` 未映射 → unknown → 零对齐；漏 `C22` |
| ADV08 | 0.75 | **OCR 识别 → 无检测层** | D33 两边都没读到，无任何信号 |
| **ADV10** | **0.83（错值）** | **OCR 识别 → 自动接收策略** | 字符静默纠正，七层无一报警 |
| ADV13-15 | 1.00（错） | **无对应层** | 形状合规即放行，缺存在性校验 |
| ADV17 / ADV21 | 0.67 | **OCR 识别**（格式规则正确捕获） | 水印污染 `严EANCABF52资料` → charset 命中 → 兜底，但 VLM 未恢复 |
| ADV18 | 0.00 | **OCR 识别**（正确捕获） | 模糊致 4 字段全丢，VLM 仅恢复 1 个 |

**归因分布**：格式规则误拒 3、类型判断 1、VLM 映射+对齐 1、OCR 识别 5、无对应层 3。

**格式规则这一层是双刃的**：它正确抓住 ADV17/21 的水印污染（真阳性），
同时误拒 ADV01/02/03 的合法异质编号（假阳性）。
`dataset_induced` 这个 origin 标记，在真实异质数据上第一次兑现了它预告的风险。

## 6. 被证伪的假设

1. **「未知设备类型会安全降级到 `unknown` 并触发兜底」——证伪。**
   三张异类图纸全部被静默吸收进风机类型，零兜底，其中两张满可作答率。
2. **「字段值形状规则能拦住业务错误」——证伪。**
   形状只能判断像不像，判断不了存不存在。`9/1`、`FAN-CAB-999` 全部放行。
3. **「`origin: dataset_induced` 只是标注谨慎」——证伪，它是真实风险。**
   三张异质编号图全部被误拒，3/3。
4. **「`policy_decision_ready` 是保守口径」——部分证伪。**
   它继承路由召回（54.5%），ADV10 证明它会把错值判为可作答。
5. **「验证器倾向采用 VLM 结果是合理默认」——被挑战。**
   唯一一次真实冲突中 OCR 对、VLM 错。

## 7. 暴露的新风险

1. **字符级静默错误完全无防护**（ADV10）。所有现有信号都在字段／实体粒度。
2. **多设备图「两边都漏同一台」不可检测**（ADV08）。`group_cardinality_uncertain`
   因为恒定触发而丧失信息量。
3. **受控映射覆盖不足会导致整页对齐归零**（ADV07，`风机组` 一词）。
4. **值规则误拒会连带压低 `decision_ready`**：ADV01–03 的 `图号` 被判非法后
   不再进入可作答集合，即使 OCR 读得完全正确。
5. **兜底误触发率 40%** 主要来自多设备图恒定不确定 + 值规则误拒。

## 8. 仍未覆盖的路径

- `aligned_spatially`：**结构上不可达**，VLM 适配器不返回 bbox，缺一侧位置数据；
- `unresolved` 对齐：本批 0 次，仍只有单元测试覆盖；
- `regex` 实体映射：本批 0 次（未出现「N号水泵」式命名）；
- 台账权威裁决：未实现，本批也没有可用台账数据；
- 冲突后的局部重识别：未实现；本批仅产生 1 条冲突，尚不足以验证。

## 9. 可以自动处理的范围

基于本批证据，以下情况系统可在无人复核下输出：

- 干净页、倾斜页、低对比度页、单纯印章遮挡页（ADV16/19/20 全部 1.00）；
- 多设备图中**编号在两个来源上精确一致**的设备（ADV09 三台全对齐）；
- 页级字段（图号、名称）在两源一致时。

前提是这些结论只在本批 21 张上成立。

## 10. 必须拒答或人工复核的范围

- **任何未通过受控映射的设备类型**（当前会被静默归入风机，必须改为拒答）；
- **多设备图中未能跨源对齐的设备**；
- **值规则判非法的字段**（当前已进入兜底，但 VLM 未必能恢复）；
- **重度模糊页**（ADV18：4 个字段全丢，VLM 只恢复 1 个）；
- **水印覆盖值列的页**（ADV17/21：`控制柜编号`、`页码` 均未恢复）；
- **一切需要"该设备是否真实存在"的判断**——系统当前没有任何能力做这件事。
